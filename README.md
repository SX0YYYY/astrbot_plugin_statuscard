# 服务器状态卡

<img src="https://raw.githubusercontent.com/SX0YYYY/astrbot_plugin_statuscard/main/logo.png" width="96" height="96" alt="服务器状态卡图标" align="right">

把服务器的 CPU、内存、磁盘、网络、进程做成一张状态图发到 QQ 群；需要时还能在资源过高、Bot 掉线或每天固定时间主动通知，并发送趋势日报与周报。

> **适用范围**：仅支持 QQ / OneBot（aiocqhttp，推荐 NapCat）；所有命令仅 AstrBot 管理员可用；出图依赖 AstrBot 配置的 T2I 服务（把页面渲染成图片的远程服务，默认即可，不需要自建）。
>
> **默认就能用。** 安装并重载插件后，管理员发送 `查看状态` 即可出图；头像默认用 QQ 头像，背景默认用内置背景，不需要先配置任何东西。

![状态卡示例](https://raw.githubusercontent.com/SX0YYYY/astrbot_plugin_statuscard/main/docs/statuscard-example.png)

*示例图为线上实拍后脱敏（主机名与群号已替换）；实际卡片会显示你的真实数据。*

## 功能特性

- **状态卡**：头像、Bot 昵称、AstrBot / NapCat 版本、运行时长、好友/群聊/群员/收发统计
- **资源概览**：CPU / 内存 / SWAP 三个环形图、系统与主机信息、磁盘占用
- **网络与磁盘**：实时上下行速度、本月流量、网络折线图、磁盘读写速度
- **网站测试**：在卡片上显示指定网站的访问状态和延迟（默认只测百度；把目标清空即关闭探测）
- **进程信息**：进程状态统计 + CPU 占用最高的进程表
- **告警与定时状态图**：资源阈值、Bot 掉线/恢复、每日定时状态图、Komari Webhook 转发
- **服务监测**：网站、端口、Docker 容器、系统服务、进程的可用性监测，异常/恢复推送到 QQ 群
- **每日日报**：每天定时发送资源趋势、异常汇总、QQ 趋势、Token 消耗、LLM 服务质量、网站延迟和 Top 进程（可勾选，默认只发前四项）；图片渲染失败会先延迟重试两次、仍失败则回退文字摘要（本地简化卡只用于状态卡与每日定时状态图）；默认关闭，可用 `预览日报` 手动查看
- **LLM 服务质量**：基于 AstrBot 自带的 provider_stats 记录统计成功率、调用延迟、首字延迟（TTFT）、按模型/会话分布；可选「LLM 服务告警」在连续失败时推送、恢复后通知（默认关闭）
- **每周周报**：每周日定时汇总此前 7 个完整自然日的趋势（与日报共用模块和模板），默认关闭，可用 `预览周报` 手动查看
- **看板导出 CSV**：服务器状态看板的「历史趋势」卡片可一键导出资源采样、进程采样、网站延迟、异常事件四份 CSV，跟随 24h/7d/30d 范围，进程名遵守看板脱敏开关；进程采样同时给出单核口径 `cpu` 与整机口径 `cpu_pct_total` 两列
- **扩展统计**：每 5 分钟记录网站延迟和 CPU/内存 Top 进程，日报展示昨日峰值和趋势
- **Web 可视化统计面板**：在 AstrBot WebUI 插件页面中查看概览、历史趋势、事件和日报，支持手动刷新
- **双语与主题**：页面和命令提示支持中英双语，日报支持浅色/深色主题，页面跟随 AstrBot 主题

## Web 可视化统计面板

插件在 AstrBot WebUI 的插件详情中提供“服务器状态看板”页面，包含四个标签：

- **概览**：CPU / 内存 / SWAP / 磁盘、网络速率、LLM 服务质量迷你卡（今日调用、成功率、连续失败）、服务监测状态、Top 进程和运行时间
- **历史**：资源 24 小时 / 7 天 / 30 天趋势和网络速率折线，可一键导出 CSV
- **事件**：最近 1 / 7 / 30 天的告警、恢复和推送失败记录
- **日报**：昨日日报摘要、关键数据和发送记录（勾选「LLM 服务质量」后含质量区块）

概览页还有「立即验证」卡片：验证推送目标（真实发送并回报回执）、验证监测项、验证 Webhook。

右上角“刷新”会显示加载状态，完成后提示“数据已更新”，失败会提示“刷新失败”。资源趋势和网络速率曲线支持鼠标悬停（触摸、键盘左右键也可以）查看具体时刻的数值；切换 24 小时 / 7 天 / 30 天时会显示加载反馈，并标注当前实际覆盖的数据范围。页面只读取聚合数值，不展示聊天内容；开启「LLM 服务质量」后日报页会展示模型名和会话 ID 前 8 位等聚合标识；文案跟随 WebUI 语言，主题跟随明暗模式，接口由 AstrBot dashboard 鉴权保护。

两点容易混淆，展开说明：

- **看板脱敏与状态卡相互独立**：在“状态卡显示 → 显示高级选项 → Web 看板脱敏项”单独设置，全部不勾即看板不脱敏，不会跟随状态卡的设置。三处隐藏效果见「数据口径 → 脱敏口径」。
- **历史趋势是滚动窗口**：看板的「24 小时 / 7 天 / 30 天」以当前时刻为终点，日报统计的是「昨天这个自然日」，两者数值不会完全一致。详见「数据口径 → 时间窗口」。

## 国际化与主题

- **页面语言**：跟随 AstrBot WebUI 界面语言（已提供 `zh-CN` / `en-US` 两套文案）。
- **命令提示语言**：在“状态卡显示 → 命令提示语言”设置，只影响 QQ 命令提示。
- **日报主题**：在“日报 → 日报主题”设置 `light`（默认）/ `dark`，只影响日报图片。
- **状态卡主题**：目前固定深色，浅色主题在后续版本提供。
- **无障碍**：页面支持键盘左右方向键切换标签、`aria` 标签和减少动效；表格使用语义化表头，状态同时用文字和颜色表示。

## 平台支持

本插件面向 **QQ / OneBot（aiocqhttp，推荐 NapCat）**。

好友数、群聊数、群员数、Bot 头像、NapCat 版本等数据都依赖 OneBot 接口；Telegram、Discord、飞书、WebChat 等平台没有适配，`查看状态` 会直接提示“不支持”，不再生成缺数据的卡片。`状态卡诊断` 仍可在这些平台用于检查插件状态（仅管理员）。

## 安装

### 环境要求

- AstrBot `>=4.26.7,<5`（已在 4.26.7、4.27.0、4.29.x 验证加载与页面 API）
- Python 3.11+（跟随 AstrBot 要求）
- 一个可用的 QQ / OneBot 连接（推荐 NapCat）
- 能访问 AstrBot 配置的 T2I 渲染服务（默认远程）

### 版本兼容说明

| AstrBot 版本 | 状态 |
|---|---|
| 4.29 及以上 | **完整体验**：所有功能均已验证 |
| 4.26.7 / 4.27.0 | **已验证加载**：插件能正常加载、命令可用、页面 API 已注册、状态卡与日报均可渲染；出图调用同一个 T2I 接口（低版本上未做过真实出图验证，遇到问题请提 issue） |

4.26.7 与 4.27.0 上做过真实的插件加载验证（AstrBot 自己的 `PluginManager` 加载、命令注册、页面路由注册、状态卡与日报 HTML 渲染全部通过）。这两个版本上未做的是「浏览器里打开 Web 看板」这类界面级验证，如果你在这两个版本上遇到页面显示问题，请提 issue 反馈。

### 安装步骤

**方式一：插件市场（推荐）**

在 AstrBot WebUI 的插件市场搜索“服务器状态卡”或 `astrbot_plugin_statuscard`，安装后重载插件即可。

**方式二：手动安装**

1. 从 [Releases](https://github.com/SX0YYYY/astrbot_plugin_statuscard/releases) 下载最新 `astrbot_plugin_statuscard-v<版本>.tgz`，解压后把 `astrbot_plugin_statuscard` 目录放到 AstrBot 的 `data/plugins/` 下（或直接 `git clone` 仓库）。
2. 安装依赖：用 **AstrBot 所在虚拟环境的 Python** 进入插件目录执行 `python -m pip install -r requirements.txt`（部分 AstrBot 版本会自动处理插件依赖）。
3. 重启 AstrBot，或在 WebUI 的插件管理页重载插件。
4. 确认 AstrBot 的 T2I 渲染服务可用（一般保持默认即可，出图失败时日志会给出原因）。
5. 由 AstrBot 管理员在私聊发 `查看状态`，或在群里发 `@bot 查看状态`。

> 所有命令都仅 AstrBot 管理员可用。普通群友触发不会执行，也不会出图。

## 快速开始

第一次使用只需要记住四件事：

1. **直接发 `查看状态`**：默认配置就能出图。
2. **想换头像/背景**：进插件配置页，把“头像来源”或“背景来源”改成“自定义上传”，上传图片后保存。
3. **想收告警**：在“告警与每日定时状态图”里打开开关，填一个 QQ 群号；需要服务监测时再到“服务可用性监测”里添加目标。
4. **想看日报/周报**：在“日报（趋势图）”里开启每日日报（需要周报就再开“启用每周周报”），或直接用 `预览日报` / `预览周报` 手动查看。

## 命令

以下命令均仅 AstrBot 管理员可用。

| 命令 | 说明 |
|---|---|
| `查看状态` | 生成并发送状态图 |
| `测试通知` | 向当前会话与实际生效的推送目标发送一条测试通知（重复目标自动去重），验证推送链路 |
| `立即检测` | 立即检查所有监测目标，只返回异常项和汇总 |
| `状态卡诊断` | 输出平台、OneBot、告警/监测/静默状态、最近采集与渲染耗时、最近推送结果 |
| `预览日报` | 生成昨日日报并发送到当前会话 |
| `预览周报` | 按截至昨天的最近 7 天生成周报并发送到当前会话（定时周报统计上一个完整自然周，两者窗口不同属正常） |

### 触发方式

- 私聊：直接发 `查看状态`
- 群聊：`@bot 查看状态`
- 状态查询只有 `查看状态` 一个命令，没有别名

配置页分为七个分组：**状态卡显示、头像、背景、告警与每日定时状态图、日报（趋势图）、服务可用性监测、通知中心（可选，放最后）**。默认只显示常用项；各分组有独立的「显示高级选项」开关（显示 / 告警 / 监测 / 日报），打开后才出现阈值、时区、脱敏等精细设置。

### 状态卡显示

常用：

- **输出图片宽度（像素）**：1170–2880。越大越清晰、文件越大、出图越慢；高度随内容自动扩展。默认 1170。
- **命令提示语言**：`zh-CN` 或 `en-US`，只影响 QQ 命令提示；页面跟随 WebUI 语言。
- **进程表显示条数**：状态卡上展示 CPU 占用最高的前几个进程，1–30。
- **手机紧凑模式**：隐藏系统信息表、进程最多 5 行、放大资源百分比。
- **出图前发送“生成中”提示**：建议开启。

高级（打开“显示高级选项”）：

- **同一会话冷却**：默认 10 秒，避免连续刷图。
- **网站测试目标**：状态卡和日报共用；默认只测百度，单个目标超时 3 秒；把列表清空即完全关闭外部网站探测（日报也不再采样）。
- **网站测试缓存**：默认 60 秒。
- **磁盘挂载点**：留空自动检测；Linux 通常填 `/`，Windows 填 `C:\`。
- **时区**：状态卡、告警、监测和日报统一使用，默认 `Asia/Shanghai`。
- **状态卡脱敏项**：主机名 / 进程信息 / 网络数据 / QQ 统计。公开群建议至少勾选前两项。
- **Web 看板脱敏项**：只影响 WebUI 看板，不影响发到 QQ 的状态卡和日报；与“状态卡脱敏项”完全独立，全部不勾即看板不脱敏。
- **首次触发隐私提示**：本次运行中每个会话第一次出图前提示状态图会发送到 T2I（重启后会再提示一次）。
- **渲染超时**：默认 180 秒，只影响状态卡与每日定时状态图（超时降级为本地简化卡）；日报/周报的超时在「日报 → 高级 → 日报渲染超时」单独设置，超时先延迟重试两次再回退文字摘要。
- **记录 T2I 渲染耗时**：排查出图慢时开启，日志会记录状态卡和日报的渲染耗时。

### 告警与每日定时状态图

常用：

- **启用资源与掉线告警**：默认关闭；只控制资源阈值和掉线告警，不影响下面的每日定时状态图。
- **默认推送目标**：所有通知默认发到这里——资源告警、掉线/恢复、每日定时状态图、服务监测、日报、周报。填 QQ 群号（如 `123456789`）或完整 UMO（AstrBot 的消息来源标识，形如 `default:GroupMessage:123456789`），可填多个。**整个插件只需要填这一处**；如果用了「通知中心」且某类型被规则勾选，该类型改发规则目标、不使用这里。
- **每日定时状态图**：独立开关，可设置每天发送时间和是否发图片；关闭图片时发文字摘要。

高级（打开“显示高级告警选项”）：

- **阈值**：CPU 85% / 内存 90% / SWAP 90% / 磁盘 85% / 每核负载 2.0；**某一项设为 0 表示单独关闭这一项**（其余照常告警）。
- **采样间隔**：默认 60 秒。
- **连续超过阈值几次才告警**：默认 3 次（约 3 分钟）。
- **告警冷却**：同一规则成功告警后 1800 秒内不重复提醒。
- **恢复时发送通知**、**Bot 掉线/恢复通知**：默认开启。如果告警或监测被关闭超过 24 小时后再开启，期间的“恢复”只写入日报事件、不再补发跨度很大的恢复消息，避免把关闭时长误报成一次长时间中断。关闭「Bot 掉线/恢复通知」只停发聊天消息：掉线与恢复事件、日报中断时长仍会记录；「掉线恢复全群广播」由它自己的开关独立控制。
- **告警聚合窗口（秒）**：默认 120。第一项告警立即推送，窗口内集中出现的后续告警合并为一条汇总；设为 0 关闭聚合。
- **掉线恢复全群广播**：默认关闭。开启后 Bot 恢复上线时向它加入的全部群广播一条含掉线时间、恢复时间与离线时长的通知；支持排除群列表、逐群间隔与群数上限（用于降低风控风险）。掉线期间无法发消息，广播只在恢复后发送一次。
- **LLM 服务告警**：默认关闭。开启后按 AstrBot 的 provider_stats 记录监测 LLM 调用质量，连续失败达到阈值时推送、恢复后通知；用户主动中止不算失败，也不打断连续链。
- **平台实例 ID**：多机器人时指定平台实例，默认 `default`。
- **机器人 QQ 号（`alerts.self_id`）**：多机器人时进一步指定 QQ 号；留空表示按平台实例选择。掉线检测和卡片数据都会按这个组合选择客户端。
- **Komari Webhook**：见下方“接入 Komari Webhook”。

> 只需要填写这一处；通知中心只用于分群，不填也能正常工作。

### 日报（趋势图）

- **启用趋势日报**：默认关闭；开启后按设定时间发送趋势日报。
- **发送时间**：默认 `21:00`，建议与每日定时状态图错开。
- **启用每周周报**：默认关闭；开启后每周日按设定时间发送最近 7 天的汇总，目标与内容复用日报设置。
- **周报发送时间**：默认 `21:30`，仅周日生效。
- **日报内容**：资源趋势 / 异常汇总 / QQ 趋势 / Token 消耗 / LLM 服务质量 / 网站延迟 / Top 进程，可勾选；默认只勾选前四项。
- **发送图片**：关闭或图片失败时发送文字摘要（渲染失败会先延迟重试两次再回退）。
- **日报主题**：`light`（默认）或 `dark`，只影响日报图片。
- **趋势天数**：7–30 天，默认 7。
- **周报内容**：留空跟随「日报内容」；单独勾选后周报按自己的模块发送，与日报分开。
- **记录日报历史数据**：默认开启；每 5 分钟记录资源、网站延迟和 Top 进程，每天记录好友/群/群员/接收累计，并记录告警/监测事件。关闭后日报没有历史趋势。

高级：

- **日报推送目标（旧字段）**：默认隐藏；留空即使用「默认推送目标」。只有当日报要单独发到别的群时才填。
- **渲染超时**、**资源采样间隔**、**Top 进程数量**、**资源保留天数**、**异常事件保留天数**。

> **每日定时状态图和日报不是一回事**：
>
> | | 每日定时状态图 | 日报（趋势图） |
> |---|---|---|
> | 内容 | 当前整张状态卡图片 | 昨日资源/异常/QQ/Token/LLM 服务质量/网站/进程趋势 |
> | 默认时间 | 09:00（线上示例为 20:00） | 21:00 |
> | 开关 | `alerts.daily_summary.enabled` | `daily_report.enabled` |
> | 数据依赖 | 实时采集 | 需要 `daily_report.collect` 积累历史 |
> | 适合 | 每天报平安 | 看趋势和异常汇总 |

### 通知中心（可选）

**一句话：只有想把不同通知发到不同群时才需要它；所有通知发同一个群时完全不用配。**

不配也能用好插件：只在「告警与每日定时状态图 → 默认推送目标」填一次群号，所有通知都发到那个群。这时「通知中心」保持为空即可，它不是「第二个推送目标」。

需要分群时（例如资源告警发运维群、日报发主群），在「通知中心」添加规则：**一条规则 = 一个目标 + 勾选它要接收的类型**。可分配的类型有七种：资源告警、服务监测告警、掉线/恢复、LLM 服务告警、趋势日报、周报、定时状态图。同一类型可以被多条规则勾选，即发到多个群。

覆盖关系（唯一需要记住的规则）：

| 情况 | 该类型的通知发到哪 |
|---|---|
| 某类型被任意一条启用规则勾选 | 只发规则目标，**忽略**「默认推送目标」 |
| 某类型没有被任何规则勾选 | 发「默认推送目标」（个别模块在高级里单独配了目标时用它自己的） |
| 规则没填目标 / 没勾类型 / 被停用 | 这条规则不生效，等同于不存在 |
| 清空全部规则 | 完全回到旧行为，旧配置无需改动 |

启用状态会显示在「状态卡诊断」与配置体检里；体检只是一条正常状态提示，不影响发送。

### 服务可用性监测

- **启用服务监测**：默认关闭。
- **监测目标列表**：点“添加条目”，按类型填写：
  - 网站 / 接口：名称 + 网址（可选期望状态码、关键字、超时）
  - 端口：名称 + 主机 + 端口
  - Docker 容器：名称 + 容器名
  - 系统服务：名称 + 服务名（如 `nginx.service`）
  - 进程：名称 + 进程名或命令行关键字
- **显示高级监测选项**：
  - **监测推送目标（旧字段）**：默认隐藏；留空即使用「默认推送目标」。只有当服务监测要单独发到别的群时才填。
  - **启用维护静默**：打开后，下面的截止时间才生效。
  - **维护静默截止时间**：`YYYY-MM-DD HH:MM`；到期前只探测、不发送异常/恢复通知。
  - **抑制重复层告警**：打开后，HTTP 监测项的 `suppress_when_down` 才生效。
  - **轮询间隔**、**连续失败次数**、**告警冷却**、**恢复通知**、**HTTP 最大读取字节数**。

> 监测项类型未知、或缺少网址/端口/容器名/服务名/进程关键字时，插件启动会在日志中给出 warning，不会静默跳过；填完可以用管理员命令 `立即检测` 验证。

### 换头像

1. 打开插件配置页 → “头像”
2. 头像来源选择“自定义上传”
3. 上传一张图片
4. 保存并重载插件
5. 发一张状态卡确认

### 换背景

1. 打开插件配置页 → “背景”
2. 背景来源选择“自定义上传”
3. 上传一张图片
4. 保存并重载插件

### 开每日定时状态图

1. “告警与每日定时状态图” → “默认推送目标”填群号
2. “每日定时状态图” → 打开启用开关
3. 设置发送时间，例如 `20:00`
4. 保存后重载插件，日志会显示下一次发送时间

到点后发送的是**整张状态卡图片**，不是单独的统计报表或趋势图；如果图片渲染失败，会先降级为本地简化卡（Pillow 绘制，零外部依赖），本地卡也失败才改发一条文字摘要。

### 每日定时状态图实际是什么

- 默认在设定时间把当前状态卡图片发到“默认推送目标”
- 图片内容和手动 `查看状态` 基本一致
- 图片渲染失败时，先降级为本地简化卡；本地卡仍失败才发送一条包含 CPU、内存、磁盘、网络、进程、好友/群/收发的文字摘要
- 不会做昨天/今天对比，也不会生成单独的“日报”版面

### 开资源/掉线告警

1. “告警与每日定时状态图” → 打开“启用资源与掉线告警”
2. 填“默认推送目标”
3. 需要改阈值时，打开“显示高级告警选项”
4. 用管理员命令 `测试通知` 验证推送链路

### 加一个网站监测

1. “服务可用性监测” → 打开“启用服务监测”
2. 确认“默认推送目标”（通常填一次即可）
3. “监测目标列表” → 添加条目 → 选择“网站 / 接口”
4. 填名称和网址，例如 `博客`、`https://example.com`
5. 保存后用 `立即检测` 验证

### 加一个 Docker 容器监测

1. 添加条目 → 选择“Docker 容器”
2. 名称填 `NapCat`，容器名填 `napcat`
3. 保存后测试。运行 AstrBot 的系统用户需要有 Docker 权限

### 加一个系统服务监测

1. 添加条目 → 选择“系统服务”
2. 名称填 `Nginx`，服务名填 `nginx.service`
3. 保存后测试

### 接入 Komari Webhook

1. 打开“告警与每日定时状态图” → “显示高级告警选项”
2. 展开“Komari Webhook”，打开“启用 Webhook 接收”
3. 默认监听 `127.0.0.1:9968/webhook`
4. 在 Komari 后台添加 Webhook，Body 用 `{"title":"{{title}}","message":"{{message}}"}`
5. 如果设置了 Token，在请求头加 `Authorization: Bearer <token>`
6. **强烈建议设置 Token**：插件默认开启“强制要求 Token”，此时未配置 Token 会拒绝启动 Webhook；如果主动关闭了这一项，监听地址又设为 `0.0.0.0`（暴露到本机以外）且没有 Token，插件同样会拒绝启动——否则任何人都能通过这个接口往你的 QQ 群发消息

## 权限与隐私

### 权限

- 所有命令都需要 AstrBot 管理员权限；普通用户无法触发状态卡或管理命令
- 插件页面的 6 个 Web API（概览 / 历史趋势 / 异常事件 / 日报摘要 / 历史数据导出 / 立即验证）由 AstrBot 的 dashboard 鉴权中间件保护，未登录访问一律返回 401
- 插件没有提供任何绕过权限的开关：命令固定为仅管理员

### 发送到外部服务的内容

- 状态图会发送到 AstrBot 配置的 T2I 渲染服务（默认 `https://t2i.soulter.top/text2img`），其中包含主机名、进程名、磁盘、网络、头像/昵称等
- 上传的头像/背景只保存在本机 `data/plugin_data/astrbot_plugin_statuscard/files/...`，不会上传到插件作者的服务器
- 插件会访问 QQ 头像地址 `q1.qlogo.cn`，以及“网站测试目标”中配置的网站；下载的 QQ 头像会缓存在本地 `files/avatar_cache/` 24 小时，减少重复请求，过期或下载失败时回退缓存/内置头像
- **插件不包含任何遥测或数据上报**：没有向插件作者或第三方发送统计信息。除为出图把页面内容发送给 AstrBot 配置的 T2I 服务、按你的配置探测网站和下载 QQ 头像外，数据都留在本机

### 本地保存的数据

| 位置 | 内容 | 保留 |
|---|---|---|
| `data/plugin_data/.../state.json` | 网络/磁盘 IO 采样、收发累计、告警与监测状态、最近一次推送结果、诊断快照 | 网络采样点最多 60 个（默认约 1 小时）；另含最多 200 条资源回填缓存（24 小时） |
| `data/plugin_data/.../report.db` | 资源数值采样、网站延迟、Top 进程、QQ 数量/接收累计、异常事件、日报生成记录 | 资源 30 天，事件 90 天 |
| `data/plugin_data/.../files/` | 你上传的头像和背景、QQ 头像缓存（24 小时） | 手动删除 |

- `state.json` 的 `delivery` 字段只保存最近一次主动推送的时间、类型、来源、成功/失败目标和协议回执（`retcode`、`message_id`），用于诊断；**不含消息内容**
- `state.json` 和 `report.db` 在 Linux 下会设置为 600 权限；SQLite 的 WAL 附属文件（`-wal` / `-shm`）同样限制为仅所有者可读写
- 监测 URL 写入 `report.db` 前会去掉 query、fragment **以及 `user:password@` 形式的凭据**，避免 API Key 落进本地数据库和群消息
- 网站名称、进程名会写入本地 `report.db`；在“状态卡脱敏项”中勾选“进程信息”只会隐藏**展示**，不会删除本地记录

### 脱敏

- 如果不想暴露主机名、进程名、网络或 QQ 统计，打开“显示高级选项”，在“状态卡脱敏项”中勾选对应项目
- 公开群使用前，建议至少隐藏主机名和进程信息
- Web 看板有独立开关“Web 看板脱敏项”，与状态卡脱敏互不影响（详见「数据口径 → 脱敏口径」）

### Komari Webhook 的暴露风险

Webhook 是一个 HTTP 接口，配置不当会让外部的人往你的 QQ 群发消息。插件的防护：

- **默认强制 Token**（`require_token` 默认开启）：未配置 Token 时拒绝启动 Webhook，而不是无鉴权地接收请求
- **绑定 `0.0.0.0` 且没有 Token 时拒绝启动**：只 warning 是远远不够的，因为那等于把「往你群里发消息」的权限开放给任何人
- Token 用恒时比较校验，请求体上限 64 KB
- **请不要把 Token 提交到公开仓库或写进 README 截图**

如果你确实需要在公网暴露 Webhook，请务必设置 Token，并把 Token 当作密码对待。

## 数据口径

### 采集与统计

- **发**：读取 AstrBot 数据库 `platform_stats` 的累计值。AstrBot 只在发送路径累加该表，因此是真实的“发”
- **收**：读取 `astrbot_plugin_message_stats` 的群统计 JSON，只覆盖该插件跟踪的群，图上会标注口径
- **日报接收**：用 `daily_snapshots.recv_total` 的**次日快照差值**（`snap(D+1) − snap(D)`）计算 D 日接收量。快照在每天 00:05 后记录，所以“昨日接收”取的是今天凌晨快照减去昨天凌晨快照
- **群员**：`get_group_list` 返回的各群 `member_count` 之和；同一用户跨群会重复计数
- **月流量**：插件定期采样 `psutil.net_io_counters`，**按自然月累计、每月 1 日重置**（不是从装机起累计），当月累计值保存在 `state.json`，重启不丢
- **累计上传 / 累计下载**：直接取 `psutil.net_io_counters` 的计数，范围是**服务器本次开机以来**，重启清零。它和「本月流量」的窗口不同——本月流量跨重启累加，所以重启后「本月」可能大于「累计」，不是算错
- **网络折线**：看板与日报共用 `report.db` 的资源采样（默认每 5 分钟一条，由 `daily_report.resource_sample_seconds` 决定），因此 24 小时 / 7 天 / 30 天都按所选窗口显示；关闭「记录日报历史数据」或尚无采样时，回退到 `state.json` 的最近 60 个采样点（默认约 1 小时）并在图注中注明。曲线支持悬停查看具体数值
- **网站延迟**：每 5 分钟探测一次“网站测试目标”，记录请求耗时和状态；可用率按响应状态码 **2xx/3xx** 统计（4xx/5xx 视为不可用，与“服务在应答但接口坏了”的实际含义一致），平均/峰值只统计成功请求
- **Top 进程**：每 5 分钟记录 CPU 和内存各自的 Top 进程；日报按进程名聚合昨日采样峰值，同一程序的多进程会合并显示
- **LLM 服务质量**：只读聚合 AstrBot 数据库 `data_v4.db` 的 `provider_stats` 表（插件不写入）；成功率 = 完成 / (完成 + 失败)，用户主动中止（aborted）单列、不计入失败；延迟与首字延迟（TTFT）只统计成功调用；按会话分布只展示会话 ID 前 8 位

### 时间窗口：看板的「最近 24 小时」和日报的「昨日」不是一回事

这两处最容易看岔，插件把它们分成了两种口径：

| | Web 看板「历史趋势」 | 日报「资源」段 |
|---|---|---|
| 窗口 | **滚动窗口**：以当前时刻为终点往前推 24 小时 / 7 天 / 30 天 | **自然日**：以 `display.timezone` 划分的昨天 00:00–24:00 |
| 边界 | 每次打开页面都会移动 | 每天固定，日报统计的是「昨天整天」 |
| 典型差异 | 现在是 15:30，窗口是昨天 15:30 → 今天 15:30 | 窗口是昨天 00:00 → 今天 00:00 |

**周报是第三种口径**：周日 21:30 发送，统计的是此前 7 个完整自然日（上周日 00:00 → 周六 24:00），**不含发送当天**，不会与看板的滚动窗口对齐。

所以看板的「24h」和日报的「昨日」在同一天里**数值不会完全一致**：看板窗口比日报多覆盖了今天已经过去的几个小时，也少了昨天午夜到 15:30 的一小段。

需要对齐比较时：

- 看**同一天的完整 24 小时** → 以日报为准
- 看**最近一段连续走势** → 以看板为准
- 资源采样的实际频率是 `daily_report.resource_sample_seconds`（默认 300 秒），所以再短的窗口也不会有更细的分辨率

日报的日界同样按 `display.timezone` 划分；修改时区后，日报的“昨天”会跟着移动。

### 异常事件的中断时长

日报「异常汇总」里的「中断时长」有两个来源，优先用前者：

1. **持久化的恢复时间**：告警或监测恢复时，插件会把恢复时刻写回那条异常记录的 `resolved_ts` 字段。因此即使插件在异常期间重启过，重启后依然能算出准确的中断时长。
2. **内存配对**（旧数据回退）：`resolved_ts` 为空的历史记录，按日报读取时把「告警」与「恢复」两条事件配对计算。

新产生的数据一律走第 1 种。

### 脱敏口径

脱敏规则只有一套定义，状态卡、日报和 Web 看板共用，因此**同一条规则在三处的隐藏效果一致**。注意：状态卡与日报由 `display.redact` 控制，看板由 `display.page_redact` 独立控制（一项不勾 = 看板完全不脱敏）；下表描述的是规则生效后的效果：

| 规则 | 状态卡 | 日报 | Web 看板 |
|---|---|---|---|
| `hostname` 主机名 | 概览「主机名」与系统信息里的 Host 显示「已隐藏」 | 日报抬头的主机名显示「已隐藏」 | 概览与历史里的主机名显示「已隐藏」 |
| `process` 进程信息 | 进程表的名字列全部显示「已隐藏」，并标注已脱敏 | Top 进程的进程名显示「已隐藏」 | 概览里的进程列表名字显示「已隐藏」 |
| `network` 网络数据 | 上行/下行/本月流量显示 `--`，网卡名（网络面板与系统信息）显示「已隐藏」，网络折线清空 | 不涉及 | 概览的网络速率与本月流量整体隐藏 |
| `qq_stats` QQ 统计 | 好友/群/群员/收发置空 | 整个「QQ」段显示「已按脱敏配置隐藏 QQ 统计」 | 概览与日报摘要里的 QQ 数据隐藏 |

两个开关互相独立：

- `display.redact` 控制**状态卡和日报**（发到 QQ 的内容）
- `display.page_redact` 控制 **Web 看板**（WebUI 里看到的内容）
- **两者互不继承**：`display.page_redact` 一项都不勾，就是看板完全不脱敏，不会因为状态卡勾了某个规则就跟着隐藏

也就是说，状态卡勾了「主机名」、而看板一项不勾时，状态卡和日报会隐藏主机名，**看板仍然显示真实主机名**。反过来也一样：想在看板里隐藏主机名，必须在「Web 看板脱敏项」里自己勾上。

> 这样设计是为了避免「勾了一个开关，另一个地方莫名其妙也跟着隐藏」的困惑。如果你的部署环境里 WebUI 也要对外展示，记得单独给看板勾选需要的脱敏项。

> 提示：Token 消耗与模型名属于日报的「Token」段，不受 `qq_stats` 影响。日报里的 Token 统计只有聚合数字（总量、调用次数、成功率、每日趋势）与模型名，不包含任何消息内容或用户标识。「LLM 服务质量」段（勾选后）会展示模型名和会话 ID 的前 8 位，同样只有聚合数字与标识片段，不含消息内容；模型名与会话标识不受现有四类脱敏规则控制。

## 常见问题

### 不配置能用吗？

能。默认会使用 QQ 头像、内置背景，网站测试只测百度，告警和服务监测默认关闭。

### 上传头像/背景后没有生效

- 确认“头像来源/背景来源”已经选择“自定义上传”
- 确认已经保存配置并重载插件
- 上传图片会取列表第一张；单张不能超过 10 MB
- 支持 png / jpg / webp / gif
- 如果来源选了“自定义上传”但没有上传文件，会回退 QQ 头像/内置背景，并在日志中提示

### 出图很慢

主要耗时在远程 T2I，不是采集。可以把“输出图片宽度”调小，或保留“出图前发送‘生成中’提示”。采集本身通常只需要 1 秒左右。

### 好友/群/群员显示 `--`

通常是 NapCat/OneBot 未连接，或 `get_friend_list` / `get_group_list` 超时。插件会在 30 秒后重试失败字段。检查：

```bash
journalctl -u astrbot -n 100 --no-pager | grep -i statuscard
```

### 每日定时状态图没有发

确认：

- “每日定时状态图”已启用
- 发送时间是 `HH:MM`，例如 `20:00`
- “默认推送目标”不为空
- 时区正确（默认 `Asia/Shanghai`）
- 每日定时状态图发送的是整张状态卡图片；图片失败时先降级为本地简化卡，本地卡也失败才发文字摘要
- 日志：`journalctl -u astrbot --since "10 minutes ago" | grep 每日定时状态图`

### 告警/监测没有收到

- 资源告警看“启用资源与掉线告警”
- 服务监测看“启用服务监测”和“监测目标列表”
- 默认推送目标可以填纯群号，也可以填完整 UMO
- **想在群里验证推送**：在接收告警的群里发送 `@bot 测试通知`（需要管理员）
- 管理员可以用 `测试通知`、`立即检测` 验证链路
- 服务监测需要连续失败达到设定次数才会告警，短暂抖动不会报
- 插件不监测 AstrBot 自身的 WebUI/进程；AstrBot 重启时插件也不在运行，无法自己告警自己
- Uptime Kuma 的邮件通知和本插件的群告警是两套通道；Uptime Kuma 监控 AstrBot WebUI 的 Down/Up 不会自动变成 QQ 群消息。这类 AstrBot 自身故障请用外部 Uptime Kuma / Komari 监测

### 怎么确认消息真的发到了 QQ

主动推送会直接调用 OneBot 接口并记录协议回执（`retcode`、`message_id`），可在 `状态卡诊断` 的“最近主动推送”里查看。

- 回执 `retcode=0`：QQ 侧已接受
- 日志 `OneBot 直发被拒绝`：OneBot 明确返回错误码，消息没有送达
- 日志 `OneBot 直发回执丢失`：超时或连接中断，插件**不确定** QQ 侧是否收到；此时不会重发，去群里看一下有没有这条消息即可

手动发送 `查看状态` 走消息回复通道，不经过主动推送，因此没有回执记录，这是正常现象。

**为什么不确定时不重发**：QQ 侧的回执可能因为网络抖动、NapCat 重启而丢失。插件无法区分“消息没发出去”和“发出去了但回执丢了”，为了避免群里出现两条，规则是「一条消息最多发一次」；只有确定没发出去（拿不到连接、目标类型不支持、接口地址非法）才退回 AstrBot 发送路径重试。

**发送与容错**：

- 单次发送最多等待：OneBot 直发 20 秒、回退到 AstrBot 发送路径 60 秒；超时按「可能已送达」处理，不重发
- 资源告警连续失败 3 次后停止重试（恢复通知照常发送），一次故障只记一条失败事件
- 日报/周报图片渲染失败会隔 10 分钟重试，最多 2 次；仍未成功才回退文字
- 每日定时状态图会把「今日已发送 / 已尝试」写入 `state.json`：只要当天发送时间已过、且今天还没有尝试记录，启动后会补发一次（不限于发送时间前后几分钟）；首次安装或升级当天没有标记时不补发，避免重复发送

### 掉线/恢复告警为什么没收到

- 掉线检测依赖同一个 QQ/OneBot 通道；AstrBot、NapCat 或 QQ 整体断开时，告警本身也发不出去
- 插件会在连接恢复后补发“离线 + 恢复”合并通知
- AstrBot 进程被重启或杀掉时插件不在运行，无法自己告警自己；这种情况建议用外部 Komari / Uptime Kuma 监测 AstrBot

### NapCat 重启时为什么没有报「掉线」

插件把「**确认掉线**」和「**探测失败**」分开处理：

- 只有 OneBot 明确返回 `online: false` 才算确认掉线，会触发掉线告警
- 状态查询本身失败（NapCat 容器重启、websocket 半开、5 秒超时）只是「探测失败」，插件单独计数并保持安静

这样做的原因很实际：NapCat 容器重启期间，状态查询必然失败，但这时说「Bot 已掉线」是**误报**——QQ 侧其实没掉线，只是插件暂时问不到状态。如果把探测失败当成掉线，NapCat 每次重启都会产生一条假告警。

探测失败持续太久时，日志里会出现一条 `OneBot 状态查询连续 N 次失败，暂时无法确认 Bot 在线状态`，提示你 OneBot 那边可能真的有问题，但不会往群里发消息。

### 日报/周报在哪里看

- 管理员发送 `预览日报`，会立即生成昨日日报并发送到当前会话；`预览周报` 同理，生成最近 7 天的周报。
- 在“日报”里开启“启用趋势日报”后，每天在设定时间自动发送；推送目标留空时复用“告警与每日定时状态图”的目标。需要周报再打开“启用每周周报”（每周日发送）。
- 前几天资源 7 天趋势、QQ 快照和接收趋势会显示“数据积累中”，因为历史数据从启用后才开始记录；发送量和 Token 可以回填 AstrBot 历史数据库。
- `状态卡诊断` 会显示日报开关、发送时间、目标数量、内容模块和最近一次发送结果。

### Docker/系统服务监测失败

- Docker 检查需要运行 AstrBot 的系统用户有 Docker 权限
- 系统服务使用 `systemctl is-active` 检查，服务名要带 `.service`，例如 `nginx.service`
- 端口监测填本机服务时，主机用 `127.0.0.1`

### 其他平台能用吗 / 为什么提示不受支持

本插件只支持 QQ / OneBot（aiocqhttp）。其他平台发送 `查看状态` 会直接收到“当前平台不受支持”，不再生成缺数据的卡片；`状态卡诊断` 仍可用于检查插件状态（仅管理员）。

### 网站延迟 / Top 进程为什么是空的

这两项和资源趋势一样，从开启「记录日报历史数据」后开始积累，默认每 5 分钟采样一次。部署当天只能看到“数据积累中”；次日或积累若干采样点后才会出现昨日平均/峰值和趋势图。网站目标复用“状态卡显示 → 高级 → 网站测试目标”，Top 进程数量由“日报 → 高级 → Top 进程数量”控制。

### 如何卸载和数据清理

删除插件目录、`data/config/astrbot_plugin_statuscard_config.json` 和 `data/plugin_data/astrbot_plugin_statuscard/` 即可。卸载前建议先备份 `state.json`；如需保留日报历史，同时备份 `report.db`。
