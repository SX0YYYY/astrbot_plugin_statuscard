# 服务器状态卡

<img src="logo.png" width="96" height="96" alt="服务器状态卡图标" align="right">

把服务器的 CPU、内存、磁盘、网络、进程等信息，做成一张状态图发到 QQ 群；需要时还能在服务掉线、资源过高或每天固定时间主动通知你，并发送资源/异常/QQ/Token/网站延迟/进程日报。

> **默认就能用。** 安装并重载插件后，由管理员发送 `查看状态` 即可出图；头像默认用 QQ 头像，背景默认用内置背景，不需要先配置任何东西。

## 功能特性

- **状态卡**：头像、Bot 昵称、AstrBot / NapCat 版本、运行时长、好友/群聊/群员/收发统计
- **资源概览**：CPU / 内存 / SWAP 三个环形图、系统与主机信息、磁盘占用
- **网络与磁盘**：实时上下行速度、本月流量、网络折线图、磁盘读写速度
- **网站测试**：在卡片上显示指定网站的访问状态和延迟（默认只测百度）
- **进程信息**：进程状态统计 + CPU 占用最高的进程表
- **告警与定时状态图**：资源阈值、Bot 掉线/恢复、每日定时状态图、Komari Webhook 转发
- **服务监测**：网站、端口、Docker 容器、系统服务、进程的可用性监测，异常/恢复推送到 QQ 群
- **每日日报**：每天定时发送资源趋势、异常汇总、QQ 趋势、Token 消耗、网站延迟和 Top 进程；图片失败回退文字；默认关闭，可用 `预览日报` 手动查看
- **扩展统计**：每 5 分钟记录网站延迟和 CPU/内存 Top 进程，日报展示昨日峰值和趋势
- **Web 可视化统计面板**：在 AstrBot WebUI 插件页面中查看概览、历史趋势、事件和日报，支持手动刷新
- **双语与主题**：页面和命令提示支持中英双语，日报支持浅色/深色主题，页面跟随 AstrBot 主题

## Web 可视化统计面板

插件在 AstrBot WebUI 的插件详情中提供“服务器状态看板”页面，包含四个标签：

- **概览**：CPU / 内存 / SWAP / 磁盘、网络速率、服务监测状态、Top 进程和运行时间
- **历史**：资源 24 小时 / 7 天 / 30 天趋势和网络速率折线
- **事件**：最近 1 / 7 / 30 天的告警、恢复和推送失败记录
- **日报**：昨日日报摘要、关键数据和发送记录

页面右上角的“刷新”按钮会显示加载状态，完成后短暂提示“已刷新”；刷新失败会提示“刷新失败”而不是静默无响应。

页面只读取聚合数值，不展示聊天内容、用户 ID 或 UMO。页面依赖 AstrBot 的插件页面 Web API。页面文案跟随 AstrBot WebUI 语言，主题跟随 WebUI 明暗模式。

**看板脱敏独立于状态卡**：在“状态卡显示 → 高级显示选项 → Web 看板脱敏项”里可以单独设置看板要隐藏的内容，不会影响发到 QQ 的状态卡和日报。留空时跟随“状态卡脱敏项”。

## 国际化与主题

- **页面语言**：跟随 AstrBot WebUI 界面语言，已提供 `zh-CN` 和 `en-US` 两套页面文案。
- **命令提示语言**：在“状态卡显示”中把“命令提示语言”设为 `zh-CN` 或 `en-US`。
- **日报主题**：在“日报”中把“日报主题”设为 `light`（默认）或 `dark`。
- **状态卡主题**：状态卡保持现有深色主题；浅色状态卡和本地渲染在后续版本提供。
- **无障碍**：页面支持键盘左右方向键切换标签、`aria` 标签、`prefers-reduced-motion` 减少动效；表格使用语义化表头，状态同时用文字和颜色表示。

## 平台支持

本插件面向 **QQ / OneBot（aiocqhttp，推荐 NapCat）**。

好友数、群聊数、群员数、Bot 头像、NapCat 版本等数据都依赖 OneBot 接口；Telegram、Discord、飞书、WebChat 等平台没有适配，`查看状态` 会直接提示“不支持”，不再生成缺数据的卡片。`状态卡诊断` 仍可在这些平台用于检查插件状态（仅管理员）。

## 安装

### 环境要求

- AstrBot `>=4.26.7,<5`（已在 4.26.7、4.27.0、4.29.0 验证加载与页面 API）
- Python 3.12+（跟随 AstrBot 要求）
- 一个可用的 QQ / OneBot 连接（推荐 NapCat）
- 能访问 AstrBot 配置的 T2I 渲染服务（默认远程）

### 版本兼容说明

| AstrBot 版本 | 状态 |
|---|---|
| 4.29 及以上 | **完整体验**：所有功能均已验证 |
| 4.26.7 / 4.27.0 | **已验证加载**：插件能正常加载、命令可用、页面 API 已注册、状态卡与日报均可渲染；出图走的是同一个 T2I 通道，行为与高版本一致 |

4.26.7 与 4.27.0 上做过真实的插件加载验证（AstrBot 自己的 `PluginManager` 加载、命令注册、页面路由注册、状态卡与日报 HTML 渲染全部通过）。这两个版本上未做的是「浏览器里打开 Web 看板」这类界面级验证，如果你在这两个版本上遇到页面显示问题，请提 issue 反馈。

### 安装步骤

**方式一：插件市场（推荐）**

在 AstrBot WebUI 的插件市场搜索“服务器状态卡”或 `astrbot_plugin_statuscard`，安装后重载插件即可。

**方式二：手动安装**

1. 把 `astrbot_plugin_statuscard` 目录放到 AstrBot 的 `data/plugins/` 下。
2. 安装依赖：`pip install -r requirements.txt`。部分 AstrBot 版本会自动处理插件依赖。
3. 重启 AstrBot，或在 WebUI 的插件管理页重载插件。
4. 确认 AstrBot 的 T2I 渲染服务可用（默认即可）。
5. 由 AstrBot 管理员在私聊发 `查看状态`，或在群里发 `@bot 查看状态`。

> 所有命令都仅 AstrBot 管理员可用。普通群友触发不会执行，也不会出图。

## 快速开始

第一次使用只需要记住四件事：

1. **直接发 `查看状态`**：默认配置就能出图。
2. **想换头像/背景**：进插件配置页，把“头像来源”或“背景来源”改成“自定义上传”，上传图片后保存。
3. **想收告警**：在“告警与每日定时状态图”里打开开关，填一个 QQ 群号；需要服务监测时再到“服务可用性监测”里添加目标。
4. **想看日报**：在“日报（趋势图）”里开启每日日报，或直接用 `预览日报` 查看昨日汇总。

## 命令

| 命令 | 说明 |
|---|---|
| `查看状态` | 生成并发送状态图（仅管理员） |
| `测试通知` | 向当前会话发送一条测试通知，验证推送链路（仅管理员） |
| `立即检测` | 立即检查所有监测目标，只返回异常项和汇总（仅管理员） |
| `状态卡诊断` | 输出平台、OneBot、告警/监测/静默状态、最近采集与渲染耗时、最近推送结果（仅管理员） |
| `预览日报` | 生成昨日日报并发送到当前会话（仅管理员） |

### 触发方式

- 私聊：直接发 `查看状态`
- 群聊：`@bot 查看状态`
- 状态查询只保留 `查看状态` 一个命令，不再注册其他别名

## 配置页导览

配置页按使用顺序分为六个分组：**状态卡显示、告警与每日定时状态图、日报（趋势图）、服务可用性监测、头像、背景**。默认只显示常用项；打开“显示高级选项”后才出现阈值、时区、脱敏等精细设置。

### 状态卡显示

常用：

- **输出图片宽度（像素）**：1170–2880。越大越清晰、文件越大、出图越慢；高度随内容自动扩展。默认 1170。
- **命令提示语言**：`zh-CN` 或 `en-US`，只影响 QQ 命令提示；页面跟随 WebUI 语言。
- **进程表显示条数**：状态卡上展示 CPU 占用最高的前几个进程，3–20。
- **手机紧凑模式**：隐藏系统信息表、进程最多 5 行、放大资源百分比。
- **出图前发送“生成中”提示**：建议开启。

高级（打开“显示高级显示选项”）：

- **同一会话冷却**：默认 10 秒，避免连续刷图。
- **网站测试目标**：状态卡和日报共用；默认只测百度，单个目标超时 3 秒。
- **网站测试缓存**：默认 60 秒。
- **磁盘挂载点**：留空自动检测；Linux 通常填 `/`，Windows 填 `C:\`。
- **时区**：状态卡、告警、监测和日报统一使用，默认 `Asia/Shanghai`。
- **状态卡脱敏项**：主机名 / 进程信息 / 网络数据 / QQ 统计。公开群建议至少勾选前两项。
- **Web 看板脱敏项**：只影响 WebUI 看板，不影响发到 QQ 的状态卡和日报；留空时跟随“状态卡脱敏项”。
- **首次触发隐私提示**：每个会话第一次出图前提示状态图会发送到 T2I。
- **渲染超时**：默认 180 秒，超时回退文字摘要。
- **记录 T2I 渲染耗时**：排查出图慢时开启，日志会记录状态卡和日报的渲染耗时。

### 告警与每日定时状态图

常用：

- **启用资源与掉线告警**：默认关闭；只控制资源阈值和掉线告警，不影响下面的每日定时状态图。
- **推送目标**：填 QQ 群号（如 `123456789`）或完整 UMO；资源告警、掉线告警、每日定时状态图和监测默认都发到这里。
- **每日定时状态图**：独立开关，可设置每天发送时间和是否发图片；关闭图片时发文字摘要。

高级（打开“显示高级告警选项”）：

- **阈值**：CPU 85% / 内存 90% / SWAP 90% / 磁盘 85% / 每核负载 2.0。
- **采样间隔**：默认 60 秒。
- **连续超过阈值几次才告警**：默认 3 次（约 3 分钟）。
- **告警冷却**：同一规则成功告警后 1800 秒内不重复提醒。
- **恢复时发送通知**、**Bot 掉线/恢复通知**：默认开启。
- **平台实例 ID**：多机器人时指定平台实例，默认 `default`。
- **Komari Webhook**：见下方“接入 Komari Webhook”。

> 每日定时状态图和服务监测默认复用“推送目标”，通常只需要在这里填一次。

### 日报（趋势图）

- **启用每日日报**：默认关闭；开启后按设定时间发送趋势日报。
- **发送时间**：默认 `21:00`，建议与每日定时状态图错开。
- **推送目标**：留空复用“告警与每日定时状态图”的推送目标。
- **日报内容**：资源趋势 / 异常汇总 / QQ 趋势 / Token 消耗 / 网站延迟 / Top 进程，可勾选；默认只勾选前四项。
- **发送图片**：关闭或图片失败时发送文字摘要。
- **日报主题**：`light`（默认）或 `dark`，只影响日报图片。
- **趋势天数**：7–30 天，默认 7。
- **记录日报历史数据**：默认开启；每 5 分钟记录资源、网站延迟和 Top 进程，每天记录好友/群/群员/接收累计，并记录告警/监测事件。关闭后日报没有历史趋势。

高级：

- **渲染超时**、**资源采样间隔**、**Top 进程数量**、**资源保留天数**、**异常事件保留天数**。

> **每日定时状态图和日报不是一回事**：
>
> | | 每日定时状态图 | 日报（趋势图） |
> |---|---|---|
> | 内容 | 当前整张状态卡图片 | 昨日资源/异常/QQ/Token/网站/进程趋势 |
> | 默认时间 | 09:00（线上示例为 20:00） | 21:00 |
> | 开关 | `alerts.daily_summary.enabled` | `daily_report.enabled` |
> | 数据依赖 | 实时采集 | 需要 `daily_report.collect` 积累历史 |
> | 适合 | 每天报平安 | 看趋势和异常汇总 |

### 服务可用性监测

- **启用服务监测**：默认关闭。
- **监测推送目标**：留空自动使用上面的告警推送目标。
- **监测目标列表**：点“添加条目”，按类型填写：
  - 网站 / 接口：名称 + 网址（可选期望状态码、关键字、超时）
  - 端口：名称 + 主机 + 端口
  - Docker 容器：名称 + 容器名
  - 系统服务：名称 + 服务名（如 `nginx.service`）
  - 进程：名称 + 进程名或命令行关键字
- **显示高级监测选项**：
  - **启用维护静默**：打开后，下面的截止时间才生效。
  - **维护静默截止时间**：`YYYY-MM-DD HH:MM`；到期前只探测、不发送异常/恢复通知。
  - **抑制重复层告警**：打开后，HTTP 监测项的 `suppress_when_down` 才生效。
  - **轮询间隔**、**连续失败次数**、**告警冷却**、**恢复通知**、**HTTP 最大读取字节数**。

> 监测项类型未知、或缺少网址/端口/容器名/服务名/进程关键字时，插件启动会在日志中给出 warning，不会静默跳过；填完可以用管理员命令 `立即检测` 验证。

### 头像

- **头像来源**：`默认（QQ 头像）` 或 `自定义上传`。
- **上传头像图片**（仅自定义上传时显示）：png / jpg / webp / gif，单张不超过 10 MB，取列表第一张。
- **状态图显示的 Bot 名称**：留空自动读取 QQ 昵称。

### 背景

- **背景来源**：`默认（内置背景）` 或 `自定义上传`。
- **上传背景图片**（仅自定义上传时显示）：png / jpg / webp / gif，单张不超过 10 MB，取列表第一张。

## 常见场景

### 换头像

1. 打开插件配置页 → “头像”
2. 头像来源选择“自定义上传”
3. 上传一张图片
4. 保存并重载插件
5. 发一张状态卡确认

### 换背景

1. 打开插件配置页 → “背景”
2. 背景来源选择“自定义上传”
3. 上传一张图片
4. 保存并重载插件

### 开每日定时状态图

1. “告警与每日定时状态图” → “推送目标”填群号
2. “每日定时状态图” → 打开启用开关
3. 设置发送时间，例如 `20:00`
4. 保存后重载插件，日志会显示下一次发送时间

到点后发送的是**整张状态卡图片**，不是单独的统计报表或趋势图；如果图片渲染失败，才会改发一条文字摘要。

### 每日定时状态图实际是什么

- 默认在设定时间把当前状态卡图片发到“推送目标”
- 图片内容和手动 `查看状态` 基本一致
- 图片渲染失败时，发送一条包含 CPU、内存、磁盘、网络、进程、好友/群/收发的文字摘要
- 不会做昨天/今天对比，也不会生成单独的“日报”版面

### 开资源/掉线告警

1. “告警与每日定时状态图” → 打开“启用资源与掉线告警”
2. 填“推送目标”
3. 需要改阈值时，打开“显示高级告警选项”
4. 用管理员命令 `测试通知` 验证推送链路

### 加一个网站监测

1. “服务可用性监测” → 打开“启用服务监测”
2. 确认“推送目标”（留空会复用告警目标）
3. “监测目标列表” → 添加条目 → 选择“网站 / 接口”
4. 填名称和网址，例如 `博客`、`https://example.com`
5. 保存后用 `立即检测` 验证

### 加一个 Docker 容器监测

1. 添加条目 → 选择“Docker 容器”
2. 名称填 `NapCat`，容器名填 `napcat`
3. 保存后测试。运行 AstrBot 的系统用户需要有 Docker 权限

### 加一个系统服务监测

1. 添加条目 → 选择“系统服务”
2. 名称填 `Nginx`，服务名填 `nginx.service`
3. 保存后测试

### 接入 Komari Webhook

1. 打开“告警与每日定时状态图” → “显示高级告警选项”
2. 展开“Komari Webhook”，打开“启用 Webhook 接收”
3. 默认监听 `127.0.0.1:9968/webhook`
4. 在 Komari 后台添加 Webhook，Body 用 `{"title":"{{title}}","message":"{{message}}"}`
5. 如果设置了 Token，在请求头加 `Authorization: Bearer <token>`
6. 如果 Webhook 需要暴露到本机以外，建议同时打开“强制要求 Token”；未配置 Token 时插件会拒绝启动 Webhook，而不是无鉴权接收

## 权限与隐私

- 所有命令都需要 AstrBot 管理员权限；普通用户无法触发状态卡或管理命令
- 状态图会发送到 AstrBot 配置的 T2I 渲染服务（默认 `https://t2i.soulter.top/text2img`），其中包含主机名、进程名、磁盘、网络、头像/昵称等
- 上传的头像/背景只保存在本机 `data/plugin_data/astrbot_plugin_statuscard/files/...`，不会上传到插件作者的服务器
- 插件会访问 QQ 头像地址 `q1.qlogo.cn`，以及“网站测试目标”中配置的网站
- 如果不想暴露主机名、进程名、网络或 QQ 统计，打开“显示高级显示选项”，在“状态卡脱敏项”中勾选对应项目
- 公开群使用前，建议至少隐藏主机名和进程信息
- 日报数据库 `data/plugin_data/astrbot_plugin_statuscard/report.db` 保存资源数值采样、网站延迟、Top 进程、QQ 数量/接收累计、异常事件和日报生成记录；不保存聊天消息、用户 ID、UMO 或 Token 密钥
- 网站名称、进程名会写入本地 `report.db`；在“状态卡脱敏项”中勾选“进程信息”只会隐藏展示，不会删除本地记录
- 监测 URL 写入 `report.db` 前会去掉 query 和 fragment；含 `?token=` 等参数的地址不会把参数持久化
- `state.json` 的 `delivery` 字段只保存最近一次主动推送的时间、类型、来源、成功/失败目标和数量，用于诊断；不含消息内容
- `state.json` 和 `report.db` 在 Linux 下会尝试设置为 600 权限；资源/网站/进程数据默认保留 30 天，事件默认保留 90 天

## 数据口径

- **发**：读取 AstrBot 数据库 `platform_stats` 的累计值。AstrBot 只在发送路径累加该表，因此是真实的“发”
- **收**：读取 `astrbot_plugin_message_stats` 的群统计 JSON，只覆盖该插件跟踪的群，图上会标注口径
- **群员**：`get_group_list` 返回的各群 `member_count` 之和；同一用户跨群会重复计数
- **月流量/网络折线**：插件每 60 秒采样 `psutil.net_io_counters`，从插件首次运行开始累计，状态保存在 `state.json`，重启不丢
- **网络折线**：图上绘制最近 60 个采样点（默认约 1 小时），采样历史最多保留 180 个点；纯 SVG 绘制，不依赖 JS
- **网站延迟**：每 5 分钟探测一次“网站测试目标”，记录请求耗时和状态；可用率按“没有网络错误”统计，平均/峰值只统计成功请求
- **Top 进程**：每 5 分钟记录 CPU 和内存各自的 Top 进程；日报按进程名聚合昨日采样峰值，同一程序的多进程会合并显示

## 常见问题

### 不配置能用吗？

能。默认会使用 QQ 头像、内置背景，网站测试只测百度，告警和服务监测默认关闭。

### 上传头像/背景后没有生效

- 确认“头像来源/背景来源”已经选择“自定义上传”
- 确认已经保存配置并重载插件
- 上传图片会取列表第一张；单张不能超过 10 MB
- 支持 png / jpg / webp / gif
- 如果来源选了“自定义上传”但没有上传文件，会回退 QQ 头像/内置背景，并在日志中提示

### 出图很慢

主要耗时在远程 T2I，不是采集。可以把“输出图片宽度”调小，或保留“出图前发送‘生成中’提示”。采集本身通常只需要 1 秒左右。

### 好友/群/群员显示 `--`

通常是 NapCat/OneBot 未连接，或 `get_friend_list` / `get_group_list` 超时。插件会在 30 秒后重试失败字段。检查：

```bash
systemctl status napcat
journalctl -u astrbot -n 100 --no-pager | grep -i statuscard
```

### 每日定时状态图没有发

确认：

- “每日定时状态图”已启用
- 发送时间是 `HH:MM`，例如 `20:00`
- “推送目标”不为空
- 时区正确（默认 `Asia/Shanghai`）
- 每日定时状态图发送的是整张状态卡图片；图片失败时才发文字摘要
- 日志：`journalctl -u astrbot --since "10 minutes ago" | grep 每日定时状态图`

### 告警/监测没有收到

- 资源告警看“启用资源与掉线告警”
- 服务监测看“启用服务监测”和“监测目标列表”
- 推送目标可以填纯群号，也可以填完整 UMO
- **想在群里验证推送**：在接收告警的群里发送 `@bot 测试通知`（需要管理员）
- 管理员可以用 `测试通知`、`立即检测` 验证链路
- 服务监测需要连续失败达到设定次数才会告警，短暂抖动不会报
- 插件不监测 AstrBot 自身的 WebUI/进程；AstrBot 重启时插件也不在运行，无法自己告警自己
- Uptime Kuma 的邮件通知和本插件的群告警是两套通道；Uptime Kuma 监控 AstrBot WebUI 的 Down/Up 不会自动变成 QQ 群消息。这类 AstrBot 自身故障请用外部 Uptime Kuma / Komari 监测

### 怎么确认消息真的发到了 QQ

主动推送会直接调用 OneBot 接口发送，并记录协议回执：

- 成功时日志形如 `OneBot 直发成功 send_group_msg -> default:GroupMessage:xxxx（message_id=12345，retcode=0）`
- 被 QQ 拒绝时日志形如 `OneBot 直发被拒绝 ...（retcode=100，说明原因）`
- `状态卡诊断` 的“最近主动推送”会显示每个目标的 `retcode` 和 `message_id`

回执是判断“QQ 侧是否真的收到”的唯一依据：`retcode=0` 表示 QQ 侧已接受；`retcode` 非 0 或日志里没有回执，说明消息没有真正送达（可能是被风控吞掉）。

> 手动发送 `查看状态` 走的是 QQ 的消息回复通道，不经过主动推送，因此没有回执记录，这是正常现象。

### 掉线/恢复告警为什么没收到

- 掉线检测依赖同一个 QQ/OneBot 通道；AstrBot、NapCat 或 QQ 整体断开时，告警本身也发不出去
- 插件会在连接恢复后补发“离线 + 恢复”合并通知
- AstrBot 进程被重启或杀掉时插件不在运行，无法自己告警自己；这种情况建议用外部 Komari / Uptime Kuma 监测 AstrBot

### Docker/系统服务监测失败

- Docker 检查需要运行 AstrBot 的系统用户有 Docker 权限
- 系统服务使用 `systemctl is-active` 检查，服务名要带 `.service`，例如 `nginx.service`
- 端口监测填本机服务时，主机用 `127.0.0.1`

### WebChat/其他平台显示 `--`

本插件只支持 QQ / OneBot（aiocqhttp）。其他平台发送 `查看状态` 会直接收到“当前平台不受支持”，不再生成缺数据的卡片；`状态卡诊断` 仍可用于检查插件状态（仅管理员）。

### 日报在哪里看

- 管理员发送 `预览日报`，会立即生成昨日日报并发送到当前会话。
- 在“日报”里开启“启用每日日报”后，每天在设定时间自动发送；推送目标留空时复用“告警与每日定时状态图”的目标。
- 前几天资源 7 天趋势、QQ 快照和接收趋势会显示“数据积累中”，因为历史数据从启用后才开始记录；发送量和 Token 可以回填 AstrBot 历史数据库。
- `状态卡诊断` 会显示日报开关、发送时间、目标数量、内容模块和最近一次发送结果。

### 网站延迟 / Top 进程为什么是空的

这两项和资源趋势一样，从启用 `daily_report.collect` 后开始积累，默认每 5 分钟采样一次。部署当天只能看到“数据积累中”；次日或积累若干采样点后才会出现昨日平均/峰值和趋势图。网站目标复用“状态卡显示 → 高级 → 网站测试目标”，Top 进程数量由 `daily_report.process_top_n` 控制。

### 如何卸载和数据清理

删除插件目录、`data/config/astrbot_plugin_statuscard_config.json` 和 `data/plugin_data/astrbot_plugin_statuscard/` 即可。卸载前建议先备份 `state.json`；如需保留日报历史，同时备份 `report.db`。
